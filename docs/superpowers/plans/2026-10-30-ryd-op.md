# Ryd op – implementeringsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fanen "Ryd op", der flytter indholdet af kendte cache-mapper til papirkurven, plus et tjek af papirkurvens fyld, som også Disk-fanen får.

**Architecture:** `ps/recycle.ps1` tager en liste og tjekker fyld. `lib/clean.mjs` udfolder `clean`-listen fra `kendt-bloat.json`, måler med `startScan` og kalder scriptet pr. mappe. `public/clean.js` er et fanemodul efter modulkontrakten i `docs/design.md`.

**Tech Stack:** Node 18+ stdlib, `node:test`, Windows PowerShell 5.1, vanilla JS-moduler.

**Spec:** `docs/superpowers/specs/2026-10-30-ryd-op-design.md`

## Global Constraints

- Aldrig permanent sletning. Kun `SHFileOperation` med `ALLOWUNDO`.
- `.ps1` kun ASCII.
- Ingen npm-afhængigheder.
- Al UI-tekst på dansk med æ, ø, å. Regler i `docs/design.md` (CSP uden inline style, tokens, 390 px, fokusring, `#tab-clean`-indkapsling).
- Mål findes i serverens egen tilstand; klienten sender rækkenavne.
- Aldrig port 4319 i test; aldrig rigtige caches i test.

## Review Focus

1. En cache-mappe er selv en junction (fx npm-cache flyttet til D:) → hele stien springes over; test i Task 2.
2. En cache er større end papirkurven (NVIDIA 10,9 GB) → `too-big`, kørslen stopper, tydelig tekst; test i Task 2 med falsk `runPowerShell`.
3. Browseren kører, så filer er låst → `failed` tælles, resten flyttes, toast siger "luk programmet"; test i Task 2 (summering).
4. Klienten sender en sti eller et ukendt navn i `names` → 400, PowerShell kaldes ikke; test i Task 2.
5. "Mål igen" og "Papirkurv" samtidig, eller to kørsler → 409; test i Task 2.

### Task 1: `recycle.ps1` med liste og fyld-tjek

**Files:**
- Modify: `ps/recycle.ps1`
- Modify: `lib/disk-service.mjs` (ruten `/api/disk/recycle`, `RECYCLE_REASONS`)

**Interfaces:**
- Produces: `powershell -File ps/recycle.ps1 -ListFile <json-fil med [sti,…]> -Bytes <long>` → én JSON-linje: `{ ok: true, moved, failed }` eller `{ ok: false, reason: 'missing'|'no-bin-settings'|'bin-disabled'|'too-big'|'bin-full', maxBytes?, usedBytes? }`. Drevet tages fra første sti; alle stier skal være på samme drev.

- [ ] **Step 1:** Erstat `-Path` med `-ListFile`; læs listen med `Get-Content -Raw | ConvertFrom-Json` (ASCII-sikker: Node skriver JSON med `\uXXXX`? Nej – skriv filen som UTF-8 med BOM fra Node, så PowerShell 5.1 læser æøå i stier korrekt). `missing` kun når ingen af stierne findes.
- [ ] **Step 2:** Tilføj `SHQueryRecycleBin(string root, ref SHQUERYRBINFO)` (struct: `int cbSize; long i64Size; long i64NumItems`, `Pack = 4` på x64 er ikke nødvendig – brug `LayoutKind.Sequential` og sæt `cbSize = Marshal.SizeOf`) i `TrashGuardShell`. Efter `too-big`: `if ($used + $Bytes -gt $maxBytes * $CapacityMargin)` → `bin-full` med `usedBytes`, `maxBytes`.
- [ ] **Step 3:** Løkke: ét `Recycle()` pr. eksisterende sti; `code -ne 0 -or aborted` → `failed++`, ellers `moved++`. Svar `{ ok = $true; moved; failed }`.
- [ ] **Step 4:** `disk-service.mjs`: skriv `[target]` til `join(dataDir, 'papirkurv.json')` (UTF-8 med BOM: `'\ufeff' + JSON.stringify(...)`), kald med `-ListFile`. `result.ok && result.failed > 0` giver den gamle "Windows kunne ikke flytte det hele"-tekst (uden fejlkode). Tilføj `'bin-full'` til `RECYCLE_REASONS` som funktion af `usedBytes`/`maxBytes`: "Papirkurven har ikke plads (X GB brugt af Y GB). Windows ville slette de ældste ting i den permanent. Tøm papirkurven først."
- [ ] **Step 5:** Manuel test i scratchpad: opret `test-ryd\a.txt`, `b.txt`, hold `b.txt` åben (`[IO.File]::Open(..., 'Open', 'Read', 'None')`), kør scriptet med begge → `{"ok":true,"moved":1,"failed":1}`; `a.txt` ligger i papirkurven. Kør med `-Bytes` = `MaxCapacity × 0,95 − i64Size + 1` (papirkurven ikke tom) → `bin-full`.
- [ ] **Step 6:** `node --test` → alt består.
- [ ] **Step 7:** Commit `Papirkurv: liste og tjek af papirkurvens fyld`.

### Task 2: `lib/clean.mjs`, listen og ruterne

**Files:**
- Create: `lib/clean.mjs`, `test/clean.test.mjs`
- Modify: `kendt-bloat.json` (nøglen `clean`), `server.mjs` (opret servicen, `...clean.routes` i `POST_ROUTES`)

**Interfaces:**
- Consumes: `startScan`, `normalizePath`, `joinPath`, `createDiskRules().lockReason` fra `lib/disk.mjs`; `expandEnv` fra `lib/parse.mjs`; scriptet fra Task 1.
- Produces:
  - `expandRows(rows, { env, rules }) → Promise<[{ name, text, paths: string[] }]>` (kun rækker med ≥ 1 sti).
  - `listChildren(dir) → Promise<string[]>` (fulde stier, uden reparse points).
  - `createCleanService({ rows, rules, scanOptions, recycleScript, dataDir, runPowerShell, onLog, env = process.env }) → { routes }` med `'/api/clean/list'` → `[200, { rows: [{ name, text, paths, size, files }] }]` og `'/api/clean/run'` (`{ names }`) → `[200, { message, rows }]` eller `[400|409|500, { error }]`.

- [ ] **Step 1: Skriv de fejlende test** i `test/clean.test.mjs` (fixture under `tmpdir()`, env `{ LOCALAPPDATA: root }`, regler fra `createDiskRules` med `lockedTrees: ['%LOCALAPPDATA%\\Låst']`):
  - `expandRows: * foldes ud, junctions og manglende stier droppes` – `App\User Data\Default\Cache`, `App\User Data\Profile 1\Cache`, en junction `App\User Data\Link` → Default; rækken `{ paths: ['%LOCALAPPDATA%\\App\\User Data\\*\\Cache', '%LOCALAPPDATA%\\Findes ikke'] }` giver præcis de to rigtige `Cache`-stier.
  - `expandRows: cache-mappen er selv en junction → droppet` og `låst sti → droppet`, og en række uden stier forsvinder.
  - `listChildren springer junctions over` – mappe med `a.bin`, `under\b.bin` og en junction → `[a.bin, under]`.
  - `run: ukendt navn og sti afvises uden PowerShell` – `names: ['C:\\Windows']` og `names: ['Findes ikke']` → 400, falsk `runPowerShell` er ikke kaldt.
  - `run: summerer moved/failed og logger én recycle-post` – falsk `runPowerShell` svarer `{"ok":true,"moved":2,"failed":1}` pr. sti; to stier → `message` indeholder "3 ting var i brug" og "luk programmet", `onLog` kaldt én gang med `type: 'recycle'`, `undoable: false`.
  - `run: too-big stopper resten` – første kald `{"ok":false,"reason":"too-big","maxBytes":…}` → 400, kun ét kald.
  - `list og run samtidig → 409` – start `list` uden at afvente, `run` svarer 409.
- [ ] **Step 2:** `node --test test/clean.test.mjs` → FAIL (modulet findes ikke).
- [ ] **Step 3:** Implementér. `*` matcher ét led via `readdir(…, { withFileTypes: true })` og `isDirectory()` (Dirent for en junction er `isSymbolicLink()`, ikke `isDirectory()`). Hver endelig sti tjekkes med `lstat` (`isDirectory() && !isSymbolicLink()`) og `rules.lockReason(path, false) === null`. `run`: unikke navne, opslag i `expandRows`-resultatet fra seneste `list` (kør `list` internt, hvis det mangler), pr. sti `startScan` → `size`, `listChildren` → skriv til `join(dataDir, 'ryd-op.json')` med BOM, `runPowerShell(recycleScript, ['-ListFile', file, '-Bytes', String(size)], timeoutMs)`. Ét `busy`-flag for både `list` og `run`. Fejltekster for `too-big`/`bin-full`/`bin-disabled`/`no-bin-settings`: genbrug teksterne fra `disk-service.mjs` ved at eksportere `recycleError(result)` derfra i stedet for at kopiere dem. Svar: "Flyttede X til papirkurven." + "N ting var i brug: luk programmet og prøv igen." når `failed > 0`.
- [ ] **Step 4:** `kendt-bloat.json`: `clean` med rækkerne fra spec'en (navn, én sætning, stier). `server.mjs`: `createCleanService({ rows: knownBloatList.clean ?? Træk disk-reglerne og `onLog` ud i hver sin `const`, så begge services bruger dem.
